# Amnezia Panel

[English](README.md) | Русский

Веб-панель для собственных серверов Amnezia.

Что может администратор:

- Создавать пользователей и выдавать каждому ключ приглашения.
- Объединять несколько VPN-серверов.
- Задавать каждому пользователю срок доступа и лимит конфигов.
- Блокировать и удалять пользователей и конфиги.
- Смотреть трафик по пользователям и по серверам.

Что может пользователь:

- Зарегистрироваться по ключу приглашения.
- В личном кабинете создавать, блокировать, удалять и повторно скачивать свои конфиги.

Панель работает на отдельном VPS. VPN-серверами она управляет по SSH теми же скриптами, что и десктопный клиент AmneziaVPN (`client/server_scripts`). Поэтому она работает с серверами, которые настроены через приложение.

Архитектура описана в `docs/superpowers/specs/2026-09-26-amnezia-panel-design.md`.

## Поддерживаемые протоколы

| Контейнер | Установка из панели | Блокировка / разблокировка | Трафик | Как выдаётся конфиг |
|---|---|---|---|---|
| AmneziaWG (`amnezia-awg2`, старый `amnezia-awg`) | да (awg2) | пир удаляется / добавляется снова | да | ключ `vpn://`, `.conf`, QR |
| WireGuard (`amnezia-wireguard`) | да | пир удаляется / добавляется снова | да | ключ `vpn://`, `.conf`, QR |
| XRay VLESS (`amnezia-xray`) | да (REALITY) | клиент удаляется / добавляется снова, Xray перезапускается | да (stats API) | ключ `vpn://`, ссылка `vless://`, QR |
| OpenVPN (`amnezia-openvpn`) | да | `disable` в `ccd` / снятие; удаление отзывает сертификат в CRL | да (по сессиям) | ключ `vpn://`, `.ovpn`, QR |
| SOCKS5 (`amnezia-socks5proxy`) | да (авторизация всегда включена) | строка пользователя удаляется / добавляется снова | да (из лога 3proxy) | ссылка `socks5://`, QR |
| Telemt (`amnezia-telemt`) | да | пользователь удаляется / добавляется снова | нет | ссылка `tg://proxy`, QR |
| MTProxy (`amnezia-mtproxy`) | да | дополнительный секрет удаляется / добавляется снова (основной секрет администратора панель не трогает) | нет | ссылка `tg://proxy`, QR |
| IKEv2 (`amnezia-ipsec`) | нет, устанавливается из приложения AmneziaVPN | серийный номер добавляется в CRL центра сертификации / убирается из него; удаление также удаляет сертификат | нет | ключ `vpn://`, `.mobileconfig` |

При изменении списка клиентов Xray, SOCKS5, Telemt и MTProxy контейнер перезапускается, и его соединения на мгновение обрываются.

OpenVPN over Cloak, OpenVPN over ShadowSocks и ShadowSocks over Xray не поддерживаются: в текущих исходниках AmneziaVPN нет серверных скриптов для них.

Импортированные клиенты (созданные не через панель) можно выдать повторно, только если на сервере есть всё, что нужно клиенту:

- клиентов Xray, SOCKS5, Telemt и MTProxy — можно;
- клиентов WireGuard, AmneziaWG, OpenVPN и IKEv2 — нельзя: их закрытые ключи остались на устройстве клиента.

## Установка

Нужен Linux VPS с Docker и плагином compose, а также DNS-имя, которое указывает на этот VPS.

1. Скачайте код:

   ```bash
   git clone https://github.com/VlDubr/amnezia-client.git
   cd amnezia-client/panel/deploy
   ```

2. Создайте файл настроек:

   ```bash
   cp .env.example .env
   ```

   В `.env` задайте `PANEL_DOMAIN`, `POSTGRES_PASSWORD` и `PANEL_TZ`. Сгенерируйте мастер-ключ и впишите его в строку `PANEL_MASTER_KEY=`:

   ```bash
   openssl rand -base64 32
   ```

   > **Внимание:** `PANEL_MASTER_KEY` шифрует SSH-доступы к вашим серверам и закрытые ключи всех конфигов в базе данных. Храните копию ключа вне сервера. Без него резервную копию базы нельзя восстановить, и всем пользователям понадобятся новые конфиги.

3. Запустите стек (образ Caddy сам собирает веб-интерфейс):

   ```bash
   docker compose up -d --build
   ```

4. Создайте первого администратора (пароль будет запрошен):

   ```bash
   docker compose exec backend python -m app.cli create-admin --login admin
   ```

Откройте `https://<PANEL_DOMAIN>/admin/login` и войдите как администратор. Страница `https://<PANEL_DOMAIN>/` — вход для пользователей, учётные записи администраторов там не принимаются.

## Добавление сервера

В админке (или через `POST /api/admin/servers`) укажите адрес сервера, SSH-пользователя и пароль или закрытый ключ.

При первом подключении панель запоминает host key сервера. Затем она импортирует все найденные поддерживаемые контейнеры (см. таблицу выше) и уже существующих на них клиентов. Импортированные клиенты появляются в разделе «Конфиги без владельца» и продолжают работать. Привяжите их к пользователям, когда будете готовы.

SSH-пользователю нужен `sudo` без пароля, как и для десктопного приложения.

Если host key сервера изменился (например, после переустановки), панель перестаёт работать с этим сервером, пока администратор не примет новый ключ.

## Эксплуатация

- **Логи:** `docker compose logs -f backend`.
- **Резервные копии:** `pg_dump` выполняется каждый день в том `backups` и хранится `BACKUP_KEEP_DAYS` дней. Восстановление:

  ```bash
  gunzip -c panel-XXXX.sql.gz | docker compose exec -T db psql -U panel panel
  ```

  Используйте тот же `PANEL_MASTER_KEY`, что и раньше.
- **Обновление:**

  ```bash
  git pull
  docker compose up -d --build
  ```

  Миграции выполняются автоматически при запуске.
- **Если панель недоступна**, VPN-серверы продолжают работать. Приостанавливаются только веб-интерфейс, выдача конфигов и автоматическое истечение доступа. После перезапуска отложенная работа выполняется.

## Управление пользователями из приложения AmneziaVPN

Откройте в приложении AmneziaVPN «Настройки» → **Amnezia Panel** и войдите, указав адрес панели и логин администратора.

Там доступна та же работа с пользователями, что и в веб-админке:

- список пользователей и создание новых (ключ приглашения показывается один раз);
- лимит конфигов и последний день доступа;
- блокировка, разблокировка и удаление пользователя, выпуск нового ключа приглашения;
- выдача конфигов на любом сервере, их показ (с QR-кодом), блокировка и удаление;
- трафик по серверам.

Добавлять серверы и устанавливать протоколы можно только в веб-админке.

## API

REST API находится под `/api`. Описание OpenAPI доступно по адресу `/api/openapi.json`, интерактивная документация — `/api/docs`.

Клиенты входят через `POST /api/auth/login`:

- Браузер получает HttpOnly-cookie сессии и CSRF-cookie. Запросы, которые меняют данные, должны передавать значение CSRF-cookie в заголовке `X-CSRF-Token`.
- Остальные клиенты передают полученный токен в заголовке `Authorization: Bearer <token>`.

## Разработка

Backend (`panel/backend`, Python 3.12+, [uv](https://docs.astral.sh/uv/)):

```bash
cd panel/backend
uv sync
uv run pytest                 # unit- и API-тесты; PostgreSQL поднимается в Docker через testcontainers
uv run pytest -m integration  # настоящие контейнеры AmneziaWG/WireGuard, управление по SSH; нужен Docker
```

Чтобы использовать существующую базу вместо testcontainers, задайте `PANEL_TEST_DATABASE_URL=postgresql+asyncpg://...`.

Веб-интерфейс (`panel/web`, Node.js 20+, React + Mantine):

```bash
cd panel/web
npm ci
npm run dev        # http://localhost:5173, запросы /api уходят на backend :8000 (меняется через PANEL_API)
npm test           # тесты компонентов (Vitest + Testing Library + MSW)
npx playwright install chromium
npm run e2e        # браузерные тесты: настоящий backend с VPN-сервером в памяти + production-сборка
```

Кабинет пользователя находится по адресу `/`, админка — `/admin` (вход — `/admin/login`).

### Локальная проверка без VPN-серверов

Тестовый запуск поднимает настоящий backend, но вместо каждого VPN-сервера использует сервер AmneziaWG в памяти. Поэтому при добавлении сервера подойдут любые адрес и пароль. Docker должен быть запущен.

```bash
cd panel/backend
uv run python -m tests.e2e_server      # API на http://127.0.0.1:8765, временная база
```

Он создаёт администратора `admin` с паролем `Adm1n-Pa55w0rd!xyz`. После остановки данные пропадают.

Во втором терминале:

```bash
cd panel/web
npm ci
PANEL_API=http://127.0.0.1:8765 npm run dev   # PowerShell: $env:PANEL_API="http://127.0.0.1:8765"; npm run dev
```

Откройте `http://localhost:5173/admin/login`. В приложении AmneziaVPN укажите адрес панели `http://127.0.0.1:8765` (обычный http разрешён только для этого компьютера).
